# SCFA 内容中心 V3.0.0-dev17

## 本轮目标

在不改变“小登录窗口 -> 登录成功后才创建完整主界面”的前提下，把账号注册、登录、Token、服务器角色和只读用户列表接成真实 API，并继续保留显式离线开发模式。

## 客户端

- `PublisherConfig` 新增 `api_base_url`。
- 环境变量 `SCFA_API_URL` 可覆盖配置，便于本机联调。
- 非 localhost 的 HTTP API 会被拒绝，正式服务器必须 HTTPS。
- 配置 API 后，登录窗口进入“服务器登录”；账号密码由 `/v1/auth/login` 验证。
- 登录成功后立即调用 `/v1/auth/me` 复核 Token 和服务器角色，客户端不只相信登录响应。
- 未配置 API 时仍明确显示“开发登录”，不会伪装成服务器账号。
- “注册账号”已接真实 `/v1/auth/register`；注册接口永远只创建普通用户。
- 软件设置新增“账号服务”地址与“测试连接”。
- 远程超级管理员的“用户管理”读取 `/v1/admin/users` 真实数据；开发登录不显示虚假人数。

## 账号服务

新增 `cmd/scfa-api`：

- `GET /healthz`
- `POST /v1/auth/register`
- `POST /v1/auth/login`
- `GET /v1/auth/me`
- `POST /v1/auth/logout`
- `GET /v1/admin/users`（需要 `users.read`）

安全规则：

- 密码：PBKDF2-HMAC-SHA256，210000 次，独立随机 salt。
- Session Token：32 字节随机值；服务器只保存 SHA-256，不保存明文 Token。
- 普通注册无法指定管理员角色。
- 登录/注册有按 IP 限速。
- 账号数据库原子写入，权限 0600。
- 注册、登录、注销写入服务器 `audit.jsonl`。
- API 默认只监听 `127.0.0.1:18080`，正式公网通过 Nginx HTTPS 反代。
