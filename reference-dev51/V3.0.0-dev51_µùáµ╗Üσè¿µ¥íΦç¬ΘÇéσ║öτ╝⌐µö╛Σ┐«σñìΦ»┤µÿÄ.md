# V3.0.0-dev51 无滚动条自适应缩放修复

## 实机反馈

dev50 在关闭“窗口自动适应”后切换到 1:1 固定画布，并通过 SetScrollInfo 暴露 contentHost 的水平/垂直滚动范围。实机因此出现主页面上下、左右系统滚动条，而且这套滚动链路与当前 Win32 子控件布局并不一致，表现为滚动条存在但无法可靠拖动。

## 根因

这是 dev50 新增的设计回归，不是 Windows 系统问题。SCFA 当前 UI 的稳定要求是：主页面必须随窗口缩放适配，不能依赖页面级水平/垂直滚动条。

## dev51 修复

- 恢复 dev19-dev36 已验证的主内容缩放模型：无论“窗口自动适应”开关状态，内容画布都必须缩放到 contentHost 可见区域内。
- “窗口自动适应”只控制紧凑导航切换；关闭时保留宽侧栏，但不再切换为固定画布/滚动模式。
- 删除 updateResponsiveLayout 中所有 SetScrollInfo 主页面调用。
- contentHost 创建和每次布局时显式 ShowScrollBar(SB_BOTH, FALSE)，确保旧滚动状态不能重新出现。
- 主窗口不再处理页面级 WM_HSCROLL / WM_VSCROLL / WM_MOUSEWHEEL。
- contentHost 不再拦截页面级滚动消息。
- 移除 dev50 自定义 WM_NCHITTEST 扩展抓取逻辑，窗口四边/四角重新完全交给标准 WS_THICKFRAME。
- 主窗口创建方式恢复到 dev36 已验证的标准 Win32 样式组合：WS_CAPTION | WS_SYSMENU | WS_MINIMIZEBOX | WS_MAXIMIZEBOX | WS_THICKFRAME。
- 保留 dev49 已验证正常的文字背景绘制方案。
- 保留 dev39 锁定的页面布局和 Fluent 图标体系。

## 固定规则

主内容页禁止出现横向/纵向滚动条。窗口变小时应缩放布局与字体，而不是产生页面滚动区域。
