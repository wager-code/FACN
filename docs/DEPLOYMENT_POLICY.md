# 生产服务器部署与职责边界

Updated: 2026-09-28

本文件规定源码开发与生产服务器运维的边界，避免开发会话在信息不完整时反复修改生产环境或把部署问题误判成代码问题。

## Codex：源码负责人

Codex负责：

- 客户端/网关源码开发
- 重构、测试、本地构建
- Git 分支、提交、PR、CI
- Release/部署包准备
- 部署脚本和配置模板草稿
- 列出 API、端口、环境变量、文件变化
- 整理部署交接材料

## ChatGPT 服务器部署会话：部署/排障负责人

生产服务器相关工作优先交给 ChatGPT 部署会话：

- systemd 服务状态/部署
- Nginx 反向代理
- 端口监听、安全组、防火墙
- HTTPS/TLS证书
- 腾讯云 COS 生产权限与连通性
- Linux 权限/目录
- 环境变量
- 线上接口状态
- 403/404/405/502/TLS/超时排查
- 生产实际版本核实
- 部署顺序、回滚和生产验收

## Codex 的停止线

遇到以下范围时，Codex不要继续直接执行生产变更：

- SSH 到生产服务器执行写操作
- 修改 `/etc/systemd/system`
- `systemctl enable/start/restart/stop`
- 修改生产 Nginx 或 reload
- 修改防火墙/安全组
- 开放/关闭公网端口
- 修改生产 TLS 证书
- 写入真实 SecretId/SecretKey/Token/主密钥
- 修改生产环境变量
- 删除/覆盖生产目录或数据
- 升级正在运行的 Publication Gateway
- 在不知道当前服务器状态和回滚点时试错式改配置

Codex可以把部署准备到“最后一米”，但不要越过这条生产停止线。

## 遇到服务器任务时的固定提示

> 这一步已经进入生产服务器部署/运维范围。按照项目规则，我先停止执行生产环境变更。  
> 我会整理当前 Git commit、源码改动、CI 状态、需要部署的组件、接口/端口/环境变量变化以及当前错误，生成服务器交接单。请把交接单和服务器实际日志发给 ChatGPT 服务器部署会话继续处理。我继续负责源码部分。


## 安全规则

- 真实密钥不进入 Git、PR、Issue、日志或交接单。
- 不用“全权限”作为默认排障方法。
- 不因 403/404/502 就反复修改代码。
- 生产变更前先确认当前版本、备份和回滚方法。
- 账号服务、Publication Gateway、Nginx、COS 分层检查。
